# 복습 노트

Android와 Windows에서 사용할 수 있는 Flutter 기반 개인용 복습 앱입니다.
MVP 2부터는 .NET 10 개인 서버를 통한 기기 간 동기화를 지원하도록 개발 중입니다.

## 주요 메뉴

- 문제 풀기
- 문제 관리
- 통계
- 설정

문제 풀기 설정에서 문제 유형을 여러 개 선택하고, 양쪽 손잡이가 있는 난이도
슬라이더로 최소·최대 난이도(1~5단계)를 지정할 수 있습니다. 기본 범위는 1~5이며,
양 끝을 같은 값으로 설정하면 해당 난이도만 출제됩니다. `정답 바로 확인` 토글은
기본적으로 켜져 있으며, 끄면 학습 종료 후 정오를 확인합니다. 끝난 후 확인 모드는
풀이 중 정오 알림을 숨기고 결과 화면에 모든 문항의 정오와 답안을 표시합니다.
이 설정은 학습 세션에 저장되며 세션을 재개해도 유지됩니다.
O/X 퀴즈는 왼쪽의 큰 `O` 또는 오른쪽의 큰 `X` 버튼을 누르면 답안을 즉시 제출합니다.
별도 제출 버튼 없이 다음 문제나 결과 화면으로 진행하며, 정오 공개 시점 설정은 그대로 적용됩니다.
모든 지원 유형의 퀴즈 하단에는 `모름` 버튼이 있습니다. 누르면 선택·입력 없이 다음 문제로
진행하고 0점으로 기록하므로 정답률이 올라가지 않으며, 오답 복습에 포함됩니다. 결과에서는
일반 오답과 구분해 `모름`으로 표시하고 정답·해설을 확인할 수 있습니다.

퀴즈 결과에서 단답형 오답을 펼치면 해설 아래 `이 답안을 정답에 추가`로 제출한
문자열을 허용 정답으로 인정할 수 있습니다. 기존 정답은 유지하며 해당 풀이의 총점·정답률·
통계와 최근 오답 필터를 함께 갱신합니다. 하단 알림의 파란 `실행취소`는 정답 정의와
채점 결과를 함께 복원합니다. 다른 시도의 과거 기록은 변경하지 않습니다.
문제 편집의 허용 정답 목록에서도 추가된 답안을 유지·수정할 수 있습니다.
문항별 대소문자·띄어쓰기 설정을 따르며 동일하게 채점되는 답안은 중복 등록하지 않습니다.
등록·취소는 기기 간 동기화하며, 이후 문제나 기록이 수정되면 덮어쓰지 않고 오류를 안내합니다.

문제 유형은 O/X / 객관식 / 순서 배열형 / 단답형 / 서술형을 지원합니다.
순서 배열형은 함정 없이 필요한 단계 3~6개만 사용합니다. 선지는 풀이 시작 시 섞이고,
순서대로 눌러 답안을 만듭니다. 선지 왼쪽의 둥근 사각 배지는 미선택 시 빈 테두리,
선택 시 강조 배경과 선택 순서를 표시합니다. 선택한 선지를 다시 누르면 취소하며 `선택 초기화`로
다시 시작할 수 있습니다. 모든 단계를 한 번씩 배치한 뒤 `답안 제출`을 누르며,
전체 순서가 맞아야 정답입니다(부분 점수 없음). 결과에는 내 답·정답 순서·해설을 표시합니다.
직접 작성할 때는 단계를 정답 순서로 입력하고 화살표로 재배치합니다.
AI는 원문에 근거한 유일한 선후 관계가 있는 과정만 생성하며, 병렬·분기·순환 등
순서가 모호한 과정은 만들지 않습니다. 생성 결과의 내용과 순서는 검토 후 승인하세요.
AI 응답의 `correctOrder`는 선지 배열의 1부터 시작하는 인덱스이고, 저장 시 고유 선지 ID로
변환합니다. 세션에 섞인 선지와 정답 ID를 함께 보관하므로 재개·동기화·이후 문제 수정에도
기존 풀이의 순서와 채점 기준을 유지합니다. DB v16은 기존 데이터를 보존하고 새 정답 목록
필드만 추가합니다. 앱과 서버를 함께 업데이트해야 새 유형을 생성·동기화할 수 있습니다.

AI 단답형 생성은 정답을 단어 또는
용어 1개로 제한하며, 여러 용어의 나열·문장 설명·예/아니오 문항은 금지합니다.
여러 단어로 이루어진 하나의 전문 용어는 허용합니다. AI는 대표 정답을 먼저 등록한 뒤, 같은 개념의
동의어·약어와 정식 명칭·한국어/영어 대응어·통용 음역·인정되는 표기 변형을 폭넓게 허용 정답으로 생성합니다.
질문이 요구하는 정확성을 유지하며 다른 개념·불완전한 답·모호한 약어·오표기는 추가하지 않습니다.
단답형 작성·편집 화면의 `채점 설정`에서 문항별 `영문 대소문자 구분`과 `띄어쓰기 구분`을
설정합니다. 두 옵션의 기본값은 꺼짐(`false`)이며, AI 생성 문항에도 동일하게 적용합니다.
기본 채점은 대소문자와 모든 공백을 무시합니다. 띄어쓰기 구분을 켜면 내부 공백까지
정확히 비교하지만, 답변 앞뒤 공백은 항상 제거합니다. 옵션은 문항과 함께 저장·동기화하고,
진행 중인 풀이는 시작 당시 설정을 유지합니다. DB v14는 기존 문항을 보존하며 두 옵션만 추가합니다.
서술형은 모범답안을 생성하고 자기 채점으로 풉니다. 답안을 제출한 뒤 모범답안·해설과 비교해
`정답으로 기록` / `오답으로 기록`을 선택합니다. `정답 바로 확인`을 끄면 모든 답안을 작성한 후
자기 채점을 진행합니다. 채점 대기 답안도 저장·동기화되며, 채점 전에는 점수·풀이 통계에 포함하지 않습니다.
별도의 AI 채점 호출이나 비용은 발생하지 않습니다.

풀이 화면 제목 왼쪽의 뒤로가기 아이콘을 누르면 확인창에서 같은 폭의 `계속 풀기` / `중단하기`를 선택합니다.
중단하면 현재 세션을 종료하고 결과를 표시합니다. 이미 채점한 답안은 보존하고,
미제출·자기 채점 대기 문항은 점수와 정답률에서 제외합니다. 답안 저장 중에는 중단할 수 없습니다.

`모름` 아래 구분선 다음의 `문제 재검토`는 확인 후 현재 문제를 건너뜁니다.
새 검수 상태를 만들지 않고 기존 검수 완료(`approved`)를 검수 필요(`draft`)로 되돌리며,
다시 승인하기 전까지 새 퀴즈에 출제하지 않습니다. 건너뛴 문항은 풀이·오답 기록을 만들지 않아
점수·정답률·통계에서 제외되고, 스킵 이력은 세션 재개와 동기화에서도 유지합니다.
모든 문항을 건너뛴 경우에도 정상 종료합니다. DB v15는 기존 데이터에 스킵 여부만 추가합니다.

문제·개념 추가/수정 중 미저장 변경사항이 있으면 뒤로 가기나 개념 창의 `취소`를 누를 때
`저장 후 나가기` / `저장하지 않고 나가기` / `계속 편집`을 선택합니다. 원래 값으로 되돌린
경우 확인 없이 닫히며, 입력 오류나 저장 실패 시 편집 내용을 유지합니다. 저장 중에는 나갈 수 없습니다.

DB v13 업그레이드 시 기존 단답형(초안·직접 작성 포함)을 모두 서술형으로 전환합니다.
문제 ID·답안·해설·난이도·중요도·출처를 보존하고, 진행 중 세션의 미제출 문항도 전환합니다.
과거 풀이 기록과 완료된 세션 스냅샷은 당시 유형·점수를 유지합니다. 서버도 시작 시 기존
동기화 문항을 전환하며, 구버전 기기가 업로드한 단답형은 서술형으로 정규화합니다.
새 단답형에는 동기화 형식 버전을 기록해 재시작·동기화 때 다시 전환되지 않습니다.

## 개념 중요도와 문제

개념 추출은 한국어 설명을 유지하면서 원문에 있는 영어 전문용어를 제목과 각 개념 본문 첫 등장에
독립적으로 병기합니다. 원문에 없는 영어 명칭·약어 풀네임은 만들지 않습니다.
PDF 직접 개념 추출·AI 수정·문제 생성은 첨자를 일반 문자로 합치지 않고
LaTeX의 `_{...}` / `^{...}` 구조로 보존하도록 지시합니다. 인라인 수식은 `\(...\)`,
독립 수식은 `\[...\]`로 저장합니다. 판독이 불확실한 부분은 추측하지 않고 표시합니다.
텍스트 추출기의 첨자 감지 로직이나 기존 데이터 자동 복원은 추가하지 않습니다.

개념·AI 수정안·문제 검토·풀이·결과의 읽기 화면은 공통 수식 렌더러를 사용합니다.
긴 수식은 가로 스크롤하며, 지원되지 않거나 잘못된 LaTeX는 버리지 않고 원문으로 표시합니다.
수식을 오른쪽 클릭하거나 길게 누르면 원문을 확인하고 `LaTeX 복사`로 복사할 수 있습니다.
키보드로 수식에 포커스한 뒤 `Shift+F10`을 눌러도 같은 창을 열 수 있습니다.
입력창에서는 원문을 편집하며 저장·동기화·채점 데이터는 렌더링 결과로 바꾸지 않습니다.
기존에 첨자가 손실된 텍스트나 이전 추출 데이터는 자동으로 복원되지 않으며,
프롬프트는 인식의 완전성을 보장하지 않으므로 수학 자료는 원본 대조가 필요합니다.

자료·개념 기반 AI 생성은 서버가 요청한 개념의 ID를 문항에 직접 연결합니다.
문제 중요도는 정답을 결정하는 주개념의 최신 중요도를 따르며, 난이도와 별개입니다.
개념·자료 삭제 시 문제와 풀이 기록은 유지하고 마지막 중요도를 보존합니다.
직접 작성·수정하는 문제에도 선택적으로 `주개념`을 지정할 수 있습니다. 자료·개념·폴더
이름으로 검색하며 다른 폴더의 개념도 선택할 수 있습니다. 연결하면 개념의 최신 중요도를
따릅니다. 연결을 해제하면 자료·페이지 출처와 마지막 중요도는 유지되며 중요도 슬라이더를
직접 조정할 수 있습니다. 주개념 없이 작성하는 문제의 기본 중요도는 `보통`입니다.
기존 자료 전체 생성 문제는 개념 연결을 추측하지 않고 기본 `보통`으로 유지합니다.

자료·개념 기반 생성의 `개념 중요도 반영`은 기본 켜짐입니다. 매우 낮음~매우 높음의
가중치 1:2:3:4:5를 사용해 서버가 문항 수를 배분합니다. 수동은 지정한 총 개수를 유지하고,
자동은 보통 중요도 기준 적음 2개/보통 4개/많음 6개를 중요도에 비례해 조정합니다.
반영을 끄면 동일 비중으로 배분합니다. 수동 총 개수가 개념 수보다 적으면 높은 중요도부터
배정하며, 자동 모드는 모든 선택 개념을 처리합니다. 자료·개념 생성 화면은 제목·내용·중요도·
페이지를 가진 개념 목록과 선택 체크박스를 표시하며, 합친 학습 텍스트를 만들거나 전송하지 않습니다.
서버는 개념 하나씩 순차 호출하고, 문항 수와 목표 난이도 배열을 계산합니다. 목표 난이도는
선택한 범위를 고르게 배분하며 중요도와 무관합니다. 실제 난이도는 생성 후 AI 평가를 유지합니다.
생성 상한은 요청 하나(개념 하나)에 적용하고 전체 결과를 120개로 자르지 않습니다.
각 개념 응답의 개수·문제 형식을 검증하고, 실패한 개념은 제목과 오류를 안내하면서 성공한
문제는 Draft 검토로 넘깁니다. 자동 재호출은 하지 않습니다. 개념별 진행률과 생성/실패 개수를 표시합니다.
완료된 개념 결과는 서버 생성 이력에 체크포인트로 남지만 연결 종료 후 자동 재개 UI는 제공하지 않습니다.
출처 개념이 없는 자유 텍스트 생성은 기존 자동/수동 지침을 사용합니다.
문제 생성 화면의 `자료 이름`은 직접 입력 대신 저장된 자료를 선택하는 검색 UI입니다.
자료명·폴더 경로로 검색할 수 있고, 일반 진입에서는 자료를 바꾸거나 선택을 해제할 수 있습니다.
자료·개념 화면의 문제 생성 버튼으로 진입하면 원본 자료 이름을 자동 표시하고 선택을 잠급니다.
자료를 선택하면 검토 완료된 개념을 불러오며, 선택 해제 상태에서는 기존 학습 내용 직접 입력을 유지합니다.

OpenAI 요청은 공통 지침과 출력 스키마를 고정하고 개념 데이터·문항 수·난이도를 뒤에 배치합니다.
공식적으로 알려진 GPT-5.6/6 계열에는 explicit 입력 캐시(30분)를 사용하고, 이전/미등록 모델에는
고정 `prompt_cache_key`로 implicit 캐시를 활용합니다. 캐시 적용은 모델과 접두부 길이 등 API 조건에
따르므로 적중·비용 절감을 보장하지 않습니다. 토큰 사용량(`cached_tokens` 포함)은 서버 로그로 확인합니다.
[OpenAI 입력 캐시 문서](https://developers.openai.com/api/docs/guides/prompt-caching)를 참고하세요.

문제 풀기 설정의 `중요 개념 우선`도 기본 켜짐입니다. 기존 필터를 적용한 뒤 개념을 먼저
가중 추첨하고 그 개념의 문제를 선택하므로, 보유 문항 수가 출제 가중치를 중복 증가시키지
않습니다. 최근 오답은 1.5배, 모름은 1.75배의 제한된 복습 가중치를 적용하며 개념 중요도는
변경하지 않습니다. 같은 세션에 같은 문제를 중복 출제하지 않으며, 순서 섞기를 끄면
선정된 문제는 기존 순서로 배치합니다. 중요 개념 우선을 끄면 기존 출제 방식으로 돌아갑니다.
이 설정과 선정 문항은 세션에 저장되어 재개·동기화 시 유지됩니다.

로컬 DB v12는 중요도 컬럼을 추가하면서 기존 데이터와 풀이 기록을 보존합니다.
새 개념 연결·배분을 사용하려면 서버도 최신 코드로 재시작해야 합니다.

## 동기화 서버

Windows 앱에서는 `설정 → Local Server`에서 Port를 확인하고 `Start Server`를
누르면 됩니다. 앱은 개발 단계에서 서버 프로젝트를
찾아 `dotnet run`을 실행하고, `/health` 응답을 확인한 뒤에만 Running으로
표시합니다. 서버 로그 확인과 중지도 같은 화면에서 할 수 있습니다.
`앱 실행 시 서버 자동 시작`을 켜면 다음 Windows 앱 실행부터 서버를 자동으로
시작합니다. 설정 화면 맨 위의 상태 표시등으로 실행 상태를 확인할 수 있으며,
이미 외부에서 실행 중인 ReviewPlatform 서버는 별도로 표시하고 앱에서 종료하지
않습니다. 자동 시작의 기본값은 켜짐입니다.

LLM 설정은 서버 프로세스 설정과 분리되어 있습니다. Android와 Windows 모두
`설정 → 용도별 AI 설정`의 PDF 개념 추출, 개념 수정, 문제 생성
카드에서 Provider와 모델을 각각 직접 설정합니다. 기존에 할당한 프로필의 모델과 옵션은
용도별로 복사해 보존하며, 한 용도의 변경이 다른 용도에 영향을 주지 않습니다.
PDF 개념 추출에는 OpenAI PDF 입력 모델이 필요합니다. 저장한 변경은 서버 재시작 없이 이후 새 요청부터
적용됩니다. 같은 화면 최하단의 `API Key` 영역에서 OpenAI, Gemini, Claude 키를
저장할 수 있습니다. 키 원문은 서버가 암호화해 보관하며 이후 클라이언트로 다시
전송하지 않습니다. Gemini와 Claude 키 저장은 향후 Provider 연동을 위한 기능이며,
`설정 → LLM → 문제 생성`의 `요청 1회당 문제 생성 상한`은 자동 저장됩니다.
기본값은 기존 120개이며, 100개를 초과하면 응답 잘림·실패 위험 경고를 표시하되
저장을 막지는 않습니다. 개념 기반 자동 생성은 개념별 요청에 상한을 적용하고,
수동은 총 1~20개를 개념별로 배분한 각 요청이 상한을 지켜야 합니다.
자유 텍스트 생성은 기존처럼 응답 전체에 상한을 적용합니다. 상한은 목표 개수가 아니며
모델의 출력·컨텍스트 한도와 요청 제한 시간은 별도로 적용됩니다. 설정 변경은
저장 완료 후 시작하는 새 요청부터 적용됩니다. 기존 서버 DB는 초기화 없이
상한 컬럼을 자동 추가하고 기존 프로필에 기본값 120을 적용합니다.

현재 실제 LLM 호출 Provider는 Ollama와 OpenAI를 지원합니다.

용도별 설정과 API Key는 입력이 0.7초 동안 멈추면 자동으로 저장됩니다.
프로필 추가·이름 변경·삭제와 용도별 프로필 할당 UI는 제공하지 않습니다.
화면 상단에서 저장 대기·저장 중·완료·실패 상태를 확인할 수 있으며 실패한 저장은 재시도할 수 있습니다.
뒤로 가기나 다른 탭으로 이동할 때도 남은 변경을 먼저 저장하고, 저장할 수 없으면
계속 편집할지 변경사항을 버릴지 확인합니다. 모델 필터는 기존처럼 기기에 자동 저장됩니다.

Ollama 설정의 `컨텍스트 크기`는 입력과 출력이 함께 사용하는 토큰 공간입니다.
Ollama는 자동 또는 모델 최대 크기 이하의 수동 크기를 저장할 수 있습니다.
자동 모드는 기존 작업별 로컬 튜닝을 유지하며, 직접 지정하면 문제 생성·개념
개념 수정·문제 생성 요청에 적용합니다. OpenAI 등 클라우드 Provider의
자동 모드는 API 모델의 컨텍스트 한도를 따르며 로컬용 컨텍스트 제한과
8,000자·8페이지 PDF 분할 튜닝을 적용하지 않습니다.

OpenAI 설정에는 `Reasoning Effort · 추론 수준`을 저장할 수 있습니다.
넓은 화면에서는 모델 선택·필터 아이콘·추론 수준 슬라이더를 한 줄로 표시하며,
좁은 화면에서는 슬라이더를 다음 줄로 배치합니다. 슬라이더는 자동과 모델별로
지원되는 값 사이에서만 이동합니다.
서버에 내장된 공식 문서 기반 지원 정보에 따라 선택지가 달라지며, 자동은 API
기본값을 사용합니다. 목록에서 주황색으로 표시된 `지원 정보 미등록` 모델은
선택할 수 있지만 추론 수준은 자동만 제공됩니다. 모델 목록은 화면 진입 시와
5분마다 갱신되며, 추론 지원 정보는 앱 업데이트로 보완합니다.
공식 문서에서 확인한 GPT-6 Luna, GPT-5.6 Terra/Luna, Mini/Nano, Pro·Codex 및
o 시리즈와 날짜별 ID를 등록했습니다. 확인된 추론 모델 중 수동 설정 값이 명확하지
않은 모델은 자동만 제공합니다. 앱에 필요한 구조화 출력을 지원하지 않는 것으로
확인된 모델은 선택 목록에서 제외합니다.
모델 필드 오른쪽의 깔때기 아이콘을 누르면 필터 메뉴가 열립니다.
`구형 모델 숨기기`와 `날짜별 버전 숨기기`는 기본으로 켜져 있으며, 적용 중인 필터는
색이 채워진 아이콘으로 표시합니다.
현재 선택한 모델과 분류 미확인 모델은 유지하며, 필터는 기기별·실행 방식별로 자동
저장됩니다. Ollama는 현재 구형 분류를 적용하지 않아 설치 모델을 그대로 표시합니다.

로컬 서버를 처음 사용할 때는 `설정 → 동기화`에
`http://127.0.0.1:5080`과 임의의 접근 토큰을 먼저 저장하세요. Local Server는
이 토큰을 서버에 전달하므로 Android에도 같은 토큰을 설정할 수 있습니다.
Android에는 Local Server 실행 메뉴가 표시되지 않습니다.

PowerShell 수동 실행은 개발 또는 문제 해결 시에만 사용할 수 있습니다.

서버 실행 전 `Sync__AccessToken` 환경 변수를 설정합니다. 토큰은 저장소에 커밋하지 않습니다.

```powershell
$env:Sync__AccessToken = '<private-token>'
dotnet run --project server/ReviewPlatform.Server -- --urls http://0.0.0.0:5080
```

앱의 `설정 → 동기화`에서 PC의 사설 IP 주소(예: `http://192.168.0.10:5080`)와 같은 토큰을 저장합니다. 이후 앱 실행, 포그라운드 복귀, 로컬 데이터 변경 3초 후, 15분 주기로 자동 동기화하며 수동 동기화도 사용할 수 있습니다. HTTP 연결은 신뢰할 수 있는 개인 네트워크나 VPN에서만 사용합니다.
Windows에서 관리 중인 로컬 서버 주소를 사용할 때는 자동 동기화도 서버 준비 완료를 기다립니다.
서버가 꺼져 있거나 시작·종료 중이면 동기화 실패를 새로 기록하지 않고 3초 간격으로 준비 상태를
재확인합니다. 대기 항목이 0건이어도 서버가 준비되면 동기화하며, 실제 성공 후 이전 오류 박스를
해제합니다. 통계와 동기화 상태는 별도 관찰 스트림을 사용해 화면 진입 순서와 무관하게 갱신됩니다.

서버 테스트:

```bash
dotnet test server/ReviewPlatform.Server.Tests
```

## AI 문제 생성 서버

기본 설정은 로컬 Ollama와 Qwen3-VL 8B를 사용합니다. Ollama가 실행 중이고 모델이
설치되어 있으면 별도 API Key 없이 사용할 수 있습니다.

구조화 응답은 `qwen3-vl:8b-instruct`를 사용합니다. `qwen3-vl:8b` reasoning
variant는 일부 Ollama 버전에서 `think: false`에도 결과를 `thinking` 필드에만
반환할 수 있어 구조화 응답에는 instruct variant를 권장합니다.

```powershell
$env:Llm__Provider = 'ollama'
$env:Llm__Model = 'qwen3-vl:8b-instruct'
$env:Llm__BaseUrl = 'http://127.0.0.1:11434'
dotnet run --project server/ReviewPlatform.Server
```

`GET /api/ai/ollama/status`에서 Ollama 연결 여부와 설정된 모델의 설치 여부를
확인할 수 있습니다. 이 API도 다른 AI API와 동일한 `X-Sync-Token` 인증을
사용합니다. 서버는 Ollama를 자동 설치·실행하거나 모델을 자동으로 내려받지 않습니다.

OpenAI Provider를 활성화할 때는 `설정 → 용도별 AI 설정 → API Key`에서 키를 저장합니다.
환경 변수는 최초 서버 저장소를 구성하는 부트스트랩 용도로도 사용할 수 있습니다.

```powershell
$env:Llm__Provider = 'openai'
$env:Llm__Model = 'gpt-4o-mini'
$env:OPENAI_API_KEY = '<openai-api-key>'
# 선택 사항: 향후 Provider 연동용 키
$env:GEMINI_API_KEY = '<gemini-api-key>'
$env:ANTHROPIC_API_KEY = '<claude-api-key>'
```

`설정 → 용도별 AI 설정`에서 해당 용도의 Provider를 OpenAI로 선택한 뒤
`POST /api/ai/questions/generate`를 사용할 수 있습니다. 앱의 개념 기반 생성은
`POST /api/ai/questions/generate/stream`으로 NDJSON 진행/완료/오류 이벤트를 받습니다.
두 API 모두 접근 토큰 인증과 동일한 생성·검증 파이프라인을 사용합니다.
OpenAI 응답은 strict JSON Schema로 제한되며, 서버의 독립적인 문제 규칙 검증을 한 번 더 통과해야 저장됩니다.

앱에서는 `문제 관리 → 폴더 → AI 문제 생성` 순서로 사용합니다. 문제 수는 학습자료의 개념별 생성량을 정하는 자동 모드(적음 1~2개, 보통 3~4개, 많음 5~6개) 또는 총 문제 수를 직접 입력하는 수동 모드로 설정합니다. 생성된 문제는 모두 Draft로 저장되며 개별 승인, 수정 후 승인, 거절, 일괄 승인을 지원합니다. Draft는 승인되기 전에는 퀴즈에 출제되지 않습니다.

문제 생성 화면의 `목표 난이도` 양방향 슬라이더로 1~5 범위를 지정할 수 있습니다
(기본값 1~5, 양 끝을 같게 하면 단일 목표 수준). 선택 범위는 AI의 문항 작성 지침으로만
전달하며, 최종 난이도는 완성된 문제를 AI가 기존 기준으로 평가한 값을 그대로 저장합니다.
평가 결과가 목표 범위를 벗어나도 범위에 맞춰 고정하거나 보정하지 않습니다.

## 학습자료

폴더의 `자료 → 새 자료`에서 PDF 없이 빈 자료를 만들 수 있습니다. 자료 화면의
`개념 추가`로 제목·내용·중요도를 직접 입력하며, PDF 자료에도 같은 방식으로
개념을 추가할 수 있습니다. 직접 작성한 개념은 기본적으로 검토 완료 상태로 시작하며,
추가 창의 `검토 완료` 토글을 끄면 검토 필요 상태로 저장합니다. 페이지 출처 배지는
표시하지 않으며 PDF 추출 개념 뒤에 추가 순서대로 표시됩니다.
페이지 출처는 번호를 정렬하고 연속된 2개 이상을 `p.50 - 53`처럼 묶어 표시합니다.
중간에 빠진 페이지는 범위에 포함하지 않으며, 저장된 출처 목록은 변경하지 않습니다.
PDF 자료와 사용자 자료는 편집·검토·AI 수정안 확인·문제 생성·이동·동기화를
같은 저장소와 파이프라인으로 처리합니다. 수동 자료 생성과 개념 추가는 서버 없이도
가능하며, AI 기능은 기존 서버 연결을 사용합니다. 기존 DB 마이그레이션은 필요 없습니다.
개념 AI 수정은 원문의 의미와 정보를 보존하면서 요청한 용어·설명을 관련 문장에
자연스럽게 통합하도록 지시합니다. 관련 문장의 재구성 및 중복 제거를 허용하고,
글자 그대로 보존하거나 앞뒤에 덧붙이는 방식은 명시적인 요청에만 적용합니다.
이 지침은 모든 개념 수정 Provider에 공통 적용되며, 기존 수정안 확인 절차와
수정 대상·출처·중요도 보호 규칙은 유지됩니다.

개념 중요도는 `매우 낮음 / 낮음 / 보통 / 높음 / 매우 높음` 5단계입니다.
개념 추가·수정 창에서는 5단계 슬라이더로 중요도를 편집합니다. 개념의 검토 필요/완료 배지를
누르면 검토 상태가 즉시 전환됩니다. 중요도 배지를 누르면 전용 슬라이더 창이 열리며,
`저장`으로 반영하거나 `취소`로 닫습니다. 펼친/접힌 개념 모두 지원하며, 제목·본문·출처와
검토 상태는 중요도만 편집할 때 그대로 유지됩니다. 개념 제목을 누르면
펼치거나 접을 수 있고, 자료 상단의 `전체 펼치기 / 전체 접기`로 한꺼번에 전환합니다.
개념 화면은 단일 스크롤 뷰를 사용해 Windows의 `ListView + Tooltip` 접근성 트리 오류를
우회합니다. 제목·배지·메뉴의 호버 안내와 접근성, PC 텍스트 선택 기능은 유지합니다.
펼친 상태에서는 제목 아래에 검토 여부·중요도·출처를 표시하고, 접힌 상태에서는
말줄임 제목과 배지를 한 줄에 표시하며 중요도의 `중요도` 접두어를 생략합니다.
펼침 상태는 자료 화면을 열어 둔 동안 유지되며 개념 데이터·검토 상태에는 영향을 주지 않습니다.
AI는 먼저 핵심 이해·적용·역량 평가에 필요한 학습 가치를 판단하고, 그 범위 안에서
실제로 필요한 암기 요소 수와 암기 정확도를 평가합니다. 지엽적인 연도·인명·수치의
나열은 학습 목표나 출제 범위에 명시된 예외가 없는 한 매우 낮음·낮음으로 제한하도록
지시합니다. 추출·수정에 공통 기준을 사용하며, 기존 중요도는 자동 재평가하지 않습니다.

폴더 안의 자료와 문제는 각 항목의 `… → 이동`에서 대상 폴더를 선택해
옮길 수 있습니다. 폴더 트리와 경로 검색을 지원하며 Windows에서는 대화상자,
Android에서는 하단 시트로 표시됩니다. 이동 시 정답·풀이 기록·개념·검토 상태와
출처 연결은 유지되고, 변경한 위치는 기존 동기화로 다른 기기에 전달됩니다.
PDF를 옮겨도 해당 자료에서 생성한 문제는 자동으로 함께 이동하지 않습니다.

문제 목록에서는 박스를 클릭해 선택지·정답, 해설, 출처를 펼치거나 접을 수 있습니다.
폴더·문제 목록은 단일 스크롤 뷰를 사용해 필터·메뉴 툴팁 전환 시 발생할 수 있는
Windows AXTree 접근성 오류를 우회합니다. 툴팁과 화면 읽기 기능은 유지합니다.
문제·개념 박스는 200ms 높이·투명도 전환을 사용하며, 연속 클릭하면 현재 위치에서 반전합니다.
접히는 본문의 조작·접근성은 즉시 비활성화하고 전환 종료 후 본문을 제거합니다.
시스템의 애니메이션 줄이기 설정에서는 즉시 전환합니다. 문제 펼침 상태는 각 카드가 관리해
클릭한 카드만 재빌드하며, 목록 전체를 다시 빌드하지 않습니다. 필터로 잠시 숨겨진 문제의
펼침 상태도 복원합니다. 문제 선택만 변경할 때는 필터·정렬 결과를 재사용합니다.
문제 유형·난이도·중요도·승인 여부는 배지로 표시하며 각 상세 영역은 구분선으로 나뉩니다.
AI 생성 문제와 문장형 선지는 `~이다.`, `~해라.`, `~인가?` 등의 해라체를 사용하도록 지시합니다.
용어만으로 된 선지, O/X 표시, 단답형 정답·동의어에는 문장 종결어미를 붙이지 않습니다.
문제 배지는 펼침 여부와 무관하게 문구·크기·스타일을 유지하며, 중요도는 항상 `중요도 높음`처럼 표시합니다.
검색은 현재 폴더의 문제·정답·해설·자료명·개념명만 대상으로 합니다. 깔대기에서 유형,
승인 여부, 중요도, 자료, 난이도 범위를 필터링하고 최근 생성/수정·난이도·중요도로 정렬합니다.
체크박스로 선택한 문제는 일괄 승인·이동·삭제할 수 있고 삭제 전 대상 개수를 확인합니다.
검색·필터 변경 시 선택을 해제하며 일괄 작업은 하나의 트랜잭션으로 처리됩니다.
문제의 `연결된 개념 보기`에서는 최신 개념 내용을 확인하고 자료의 해당 개념으로 이동합니다.
자료의 각 개념에 있는 `연결된 문제 모두 보기`에는 다른 폴더로 이동한 문제도 포함되며
미승인 문제도 표시합니다. 이 역방향 연결 조회는 일반 폴더 검색 범위와 별개입니다.

`문제 관리 → 폴더 → 자료`의 PDF 가져오기 아이콘에서 PDF를 가져올 수 있습니다.
Windows에서는 폴더의 `자료` 영역 또는 PDF 가져오기 화면에 파일을 드래그 앤 드롭해도
같은 분석·저장 흐름을 사용합니다. 드래그 중 영역을 강조하며 PDF 한 개를
허용합니다. 분석 중이거나 다른 화면·대화상자 뒤에 가려진 영역에서는 드롭을 받지 않습니다.
Android에서는 기존 파일 선택 버튼을 사용합니다. 네이티브 드롭 플러그인 적용 후에는
실행 중인 앱을 종료하고 다시 빌드·실행해야 합니다(핫 리로드만으로 적용되지 않습니다).
용량 상한은 서버 설정에 따릅니다. 서버는 원본을
`server/ReviewPlatform.Server/App_Data/sources`에 보관하고, 페이지별 텍스트
레이어를 우선 추출하고, 텍스트가 부족한 페이지만 Qwen3-VL 이미지 분석으로 보완한 뒤
LLM으로 검토 필요 상태의 개념을 만듭니다. 각 개념 아래에는 검토 완료 토글, AI 수정 요청,
문제 생성 버튼이 순서대로 표시됩니다. 검토 필요 개념의 문제 생성 버튼은 비활성화되며,
검토 완료된 개념에서 생성한 문제에는 원본 PDF, 페이지, 개념 출처가 연결됩니다.
자료 제목 아래에는 `개념 추가 → 수정 요청 → 문제 생성` 버튼이 폭을 균등하게 채웁니다.
문제 생성 버튼은 해당 자료의 검토 완료된 개념을 묶어 사용하며, 검토 완료된 개념이 없으면
비활성화됩니다. 자료 단위로 생성한 문제에는 원본 자료와 입력에 포함된 페이지
출처가 연결됩니다. 수동 개념에는 페이지 출처를 붙이지 않으며 AI 수정에서도 이를 보존합니다.

개념의 직접 편집은 기존 검토 상태를 유지합니다. AI 수정안 확인 창에서 `적용`을
누르면 실제 변경된 개념만 검토 필요 상태로 바뀌며, `적용 후 검토 완료`를 누르면
변경 내용과 검토 완료 상태를 함께 저장합니다. 취소하면 기존 내용과 상태를 유지합니다.
표시명만 변경했으므로 기존 `held/approved` 데이터와 동기화 형식은 그대로 유지됩니다.

수정 요청 창에서 `새 개념 추가 허용`과 `기존 개념 삭제 허용`을 각각 켤 수 있습니다
(기본 꺼짐). 수정·삭제는 선택한 기존 개념에만 허용하며, 추가만 요청할 때는 대상을
선택하지 않아도 됩니다. 빈 자료에서도 AI 추가 요청을 사용할 수 있습니다.
AI는 수정·추가·삭제를 분리해 제안하고 확인 창에서 변경별로 적용 여부를 선택합니다.
삭제와 삭제가 포함된 연결 그룹은 기본 미선택이며, 분할·병합 등 연결된 변경은
그룹 전체를 함께 선택합니다. 응답에 빠진 개념은 유지됩니다. 새 개념의 ID는 저장 시
앱이 발급하고, PDF 근거가 없는 내용에는 페이지 출처를 붙이지 않습니다.
추가·수정 개념은 기본 검토 필요 상태로 저장되며 `적용 후 검토 완료`도 지원합니다.
개념을 삭제해도 기존 문제·풀이 기록과 자료·페이지 출처는 유지하고 개념 연결만 해제합니다.
대기 중 원본 개념이 바뀌면 적용을 중단하고 재요청을 안내합니다. 변경과 동기화 Outbox는
하나의 트랜잭션으로 저장합니다. 한 요청의 새 개념은 최대 20개, 자료 내 총 개념은
최대 200개이며 모델의 출력 한도에 따라 요청을 더 작게 나누는 것이 필요할 수 있습니다.

개념 수정 요청에는 선택한 개념의 **출처 페이지 원본 PDF**를 서버에서 묶어 첨부합니다.
중복 페이지는 한 번만 포함하고, 발췌 PDF의 페이지 번호와 원본 페이지 번호의 대응표를
프롬프트에 제공합니다. 원본 파일 해시·페이지 수를 확인하며, 원본이 없거나 다른 서버에
연결된 경우 텍스트만으로 대체하지 않고 오류를 안내합니다. 출처 없는 수동 개념은
기존처럼 텍스트로 수정합니다. 현재 PDF 첨부 수정은 지원 정보가 등록된 OpenAI PDF 입력
지원 모델에서 제공하며 Ollama에는 PDF를 전달하지 않습니다.

AI 수정 결과에는 전체 **코멘트**와 변경별 **이유**가 포함됩니다. 중요한 모호성이 있으면
변경안 대신 확인 질문을 표시하고, 같은 요청 창에서 답변을 보냅니다. 원래 요청·선택·추가/삭제
권한은 유지하고 질문·답변 이력을 다음 호출에 함께 전달합니다(최대 10회). 자동 재호출은
하지 않습니다. `요청 다시 작성`으로 최신 개념 목록을 불러와 대상을 다시 정할 수 있습니다.
변경 없는 결과도 코멘트를 표시하며, 실제 변경은 기존 수정안 검토에서 선택·확인한 뒤에만
저장합니다. 질문 진행 중 개념이 바뀌면 재요청을 요구하며 입력은 보존합니다.

상용 API 개념 수정의 작은 고정 출력 상한은 제거했습니다. **64k는 예상 출력량에 대한
안내 기준**이며 응답을 자르는 한도가 아닙니다. API에는 등록된 모델의 기술적 최대 출력량을
사용하고, PDF를 첨부하면 입력 토큰 계산 API로 사전 점검합니다. 컨텍스트 한도가 등록된
모델은 실제 입력과 여유분을 뺀 공간도 반영합니다. 미등록 출력 한도는 추측하지 않고
오류로 안내합니다. 예상량은 거친 추정이며 reasoning 토큰은 API 출력 한도에 포함됩니다.
잘린 응답은 부분 적용하지 않습니다. 서버 로그에는 입력·출력·추론 토큰과 적용 상한을
기록하며 PDF 본문·API 키는 기록하지 않습니다. 로컬 Ollama 출력 튜닝은 별도로 유지합니다.
앱과 서버를 함께 업데이트하고 서버를 재시작해야 새 수정 응답 형식을 사용할 수 있습니다.

작업 오류는 확인할 때까지 유지되는 공통 오류 확인창으로 표시하며 문구를 복사할 수 있습니다.
실패한 화면에는 공통 오류 박스를 남기고, PDF 백그라운드 작업의 실패·연결 오류는 다른 화면에서도
알립니다. 같은 작업의 동일 오류는 반복 알림을 억제하며 복구·재시도 뒤 새 실패는 다시 알립니다.

### PDF 업로드 후 직접 개념 추출

새 PDF는 업로드 후 **추출 설정 화면**으로 이동합니다. 파일명·크기·페이지 수·개념 추출
모델을 확인하고 입력 사전 점검 후 `추출 시작`을 누릅니다. 업로드만으로 AI 분석을 시작하지
않으며, 앱을 닫아도 폴더의 자료 영역에서 선택 대기 작업을 다시 열거나 이동·삭제할 수 있습니다.
앱과 서버를 함께 업데이트하고 서버를 재시작해 주세요. 구 서버의 경우 파일을 전송하기 전에
업데이트 안내를 표시해, 기존 서버가 자동으로 OCR을 시작하는 일을 방지합니다.

PDF → OpenAI PDF 입력 지원 모델 → 개념 추출의 단일 경로입니다.
OCR 처리·중간 검토·OCR 원문 대조와 동기식 가져오기 API는 제거했습니다.
한국어·중요도·검토 상태·문제 연결 파이프라인에는 기존과 같은 개념 데이터로 저장합니다.
이전 방식으로 완료한 자료·개념은 그대로 유지합니다. 미완료된 이전 작업은 자동 실행하지
않으며 추출 설정에서 직접 추출 사전 점검 후 시작해야 합니다.
입력 PDF 원본은 서버에 그대로 보존합니다. 자료 화면과 문제 생성 화면의 개념 출처 배지를 누르면
원본 슬라이드 팝업을 엽니다. 연결된 출처 페이지만 아이콘/휠로 이동하며, 확대·축소와 터치 확대/이동을 지원합니다.
이미지는 기존 PDF 렌더러로 조회하므로 LLM/OCR 호출은 없습니다. 서버 연결이 필요하며,
본 이미지는 앱 메모리에 최대 24MB·12개까지 캐시합니다. 오프라인 영구 저장은 하지 않습니다.

직접 추출은 `설정 → 용도별 AI 설정 → PDF 개념 추출`의 OpenAI 모델을 사용합니다.
`입력 사전 점검`은 실제 PDF와 프롬프트·스키마를 `/v1/responses/input_tokens`에 보내 입력 토큰 수를
확인합니다. 파일 크기, 컨텍스트, 출력 예산, TPM에 대해 `진행 가능 / 주의 필요 / 확인 불가 /
한도 회복 대기 / 분할 필요`로 안내하며, 분할 필요 상태에서는 시작할 수 없습니다.
확인 불가·주의 상태에서 진행하려면 경고를 확인해야 합니다. 점검 API의 한도 때문에 입력량을
확인하지 못한 경우에는 대기 후 재점검해야 합니다. 모델·분할 지점 변경 시 재점검합니다.

분할은 자동으로 하지 않습니다. 원본 페이지를 휠/아이콘/페이지 번호로 이동하면서
분할 지점 목록에 페이지 번호를 추가·삭제합니다. 목록 변경마다 자동으로 사전 점검을 수행합니다.
해당 경계로 실제 부분 PDF를 만들어 순서대로 보내고,
응답 페이지 번호를 원본 페이지 번호로 복원합니다. 여러 슬라이드에 걸친 개념은 같은 묶음에
유지해야 합니다. 완료된 묶음은 체크포인트에 보존하므로 실패 후에는 미완료 범위만 재개합니다.
이미 완료된 묶음의 경계나 추출 경로는 변경할 수 없습니다. 불완전한 JSON/출력 한도 초과
응답은 개념으로 저장하지 않습니다. 원본 페이지 미리보기는 수동 분할 지점을 정할 때 사용합니다.

서버 `Documents:DirectPdf:OutputSafetyThresholdTokens` 기본값 **64,000 토큰**은
**분할 권장용 소프트 기준**입니다. 예상 출력이 이 기준에 도달하면 확인 후 진행할 수 있고,
생성 중 이 기준에 도달했다는 이유로 응답을 중단하지 않습니다. 이전 `MaximumOutputTokens`와
`EstimatedOutputTokensPerPage` 설정은 더 이상 사용하지 않습니다.
API의 `max_output_tokens`는 등록된 모델의 출력 최대치와 실제 입력을 뺀 컨텍스트 여유 중 작은
값으로 정합니다(추론 포함). 출력 한도가 미등록된 모델은 임의 값으로 대체하지 않고 시작을
막습니다. 컨텍스트 정보가 없는 모델은 불확실성을 알립니다. TPM 가정 500,000, 입력 안전
상한 900,000, 컨텍스트 여유 10,000은 유지합니다.

예상 출력은 같은 모델·추론 수준·프롬프트 버전의 정상 완료 및 검증된 Usage로 보정합니다.
동일 PDF 재시도는 표본 수를 늘리지 않으며, 최소 5개 표본 전에는 `예측 자료 부족`을 표시합니다.
최근 최대 100개 표본의 페이지당 전체 출력 토큰 중앙값과 관측 최소/최대 환산 범위를 표시하고,
관측 페이지 범위 밖의 예측은 신뢰도가 낮다고 안내합니다. 이는 보장 범위나 확률 모델이 아니며,
예측값으로 API 출력 한도를 낮추지 않습니다. 불완전·실패·유효하지 않은 결과는 보정에서 제외합니다.

서버의 `Documents:StoragePath/direct-pdf-usage/`(기본 `App_Data/sources/direct-pdf-usage/`)에
요청별 `*.usage.json`(입력·출력·추론 토큰, 설정, 완료/실패 사유)과 `*.response.json`(수신한 원본 응답)을
보존합니다. 서버 재시작 후에도 실측 표본을 읽습니다. PDF·프롬프트 요청 본문·API Key는 이 기록에
넣지 않지만 **원본 응답에는 학습 내용이 포함되므로 서버 로컬의 민감한 자료로 취급**해야 합니다.
네트워크 오류처럼 응답 자체가 없는 경우에는 Usage 메타데이터만 기록합니다. 진단 파일 저장 실패는
경고 로그로 남기며 정상 추출 결과를 실패로 바꾸지 않습니다. 예전 정책의 사전 점검은 재점검해야
하며 이미 완료된 묶음과 PDF는 그대로 유지합니다.

생성 API의 TPM 헤더를 받은 경우 해당 한도를 이용하지만,
점검 API의 한도 헤더는 생성 TPM으로 오인하지 않습니다. 계정 전체의 실시간 사용량을 조회하거나
TPM을 예약하지는 못하며, 임시 429는 대기 후 최대 4회 시도합니다. 계정 Tier/모델 한도가 다르면
서버 TPM 설정을 맞춰 주세요. 직접 PDF 입력은 각 묶음이 50MB 미만이어야 합니다.

검증: HTTP 모의 응답으로 PDF 입력·입력 토큰·출력 상한·불완전 응답을 테스트하고,
실제 부분 PDF 생성/페이지 복원·원본 보존·이전 작업의 자동 호출 방지, 위젯 조작·360dp·글자 200%·두 테마를 테스트합니다.
유료 OpenAI 실호출과 Windows/Android 기기에서의 실제 원본 확대·파일 선택은 별도 확인이 필요합니다.


### 백그라운드 작업과 보존

파일 선택·드래그 앤 드롭은 PDF를 서버에 스트리밍하며, 업로드만으로 AI 호출을 시작하지 않습니다.
작업 ID·저장 대상 폴더는 클라이언트 DB에 보관합니다. 명시적으로 시작한 직접 추출은
화면을 나가거나 앱을 재시작해도 진행 상황을 조회합니다. Windows 로컬 서버 준비 전에는 조회를 보류합니다.
완료된 묶음은 서버 체크포인트에 보관하여 실패·취소 후 미완료 범위만 다시 처리합니다.
원본 PDF와 완료한 개념은 이 업데이트에서 삭제하지 않습니다. 사용자가 자료/작업 삭제를 확정할 때만 원본도 삭제합니다.
원본 슬라이드 조회는 추출 작업의 체크포인트·모델·분석 지침 버전에 의존하지 않습니다.
PDF 이미지 OCR용 모델 설정과 관련 API는 더 이상 제공하지 않습니다.

서버 Documents의 기본 안전 상한: 파일 200MB, 1,000페이지, 업로드 후 여유 공간 512MB,
실행·대기 작업 합계 8개. 직접 API에 보낼 각 묶음은 50MB 미만이어야 합니다.
개념 개수의 고정 상한은 없으며 출력 토큰 예산은 적용합니다. 문서는 자동 분할하지 않습니다.

인증된 작업 API: POST /api/documents/jobs/{id}?fileName=... (raw PDF),
GET /api/documents/jobs/{id}, GET /api/documents/jobs/{id}/result,
POST /api/documents/jobs/{id}/cancel, POST /api/documents/jobs/{id}/retry,
DELETE /api/documents/jobs/{id}, GET /api/documents/limits.
추출 설정은 GET /api/documents/jobs/{id}/extraction,
POST .../extraction/preflight, POST .../extraction/start, GET .../extraction/pages/{page}/image로 제공합니다.
완료된 자료의 원본 조회는 GET /api/documents/sources/{sourceId}/pages/{page}/image입니다.

```powershell
flutter run -d windows -t tool/ui_preview.dart
```

기존처럼 기본 `lib/main.dart`를 사용하세요. 반응형·글자 확대·복귀·입력 보호·검수
중복 제출 회귀 테스트는 `test/ui_ux_v2_test.dart`에 있습니다.
